## 关键设计

### 1. 隔离模型(不可伪造的 namespace)

```
global    → u:{user_hash}:global
workspace → u:{user_hash}:workspace:{workspace_hash}
```

- `user_hash` 是首次运行生成的随机 UUID(存于 `config/identity.json`)。
- `workspace_hash` 是对 workspace_id 的 sha256。
- namespace 由 daemon 根据**已注册 session** 推导;MCP 工具不接受任何
  `user_id`/`workspace_id` 参数。伪造其他 workspace 的请求会被路由到
  自己的 namespace,而不是目标。
- mem0 的 `user_id` 字段被用作 namespace 载体(OSS 无多 collection 隔离)。

### 2. 两条捕获管线

**A. 事实记忆**(Stop / PreCompact 触发):
```
transcript 增量 → Memory LLM scope 分类(global|workspace|discard)
→ mem0 add(infer=True) → 独立 Embedding → Qdrant Local
```

**B. 会话摘要**(Stop 触发):
```
transcript 尾部 → Summary LLM 结构化摘要
(目标/关键决定/已完成/修改文件/已知问题/未完成/后续约束)
→ mem0 add(infer=False),memory_type=session_summary
```

幂等性:SQLite 记录 (a) 每 session 的字节游标;(b) 已处理事件哈希。
捕获成功后才推进游标;失败进重试队列(60s 周期,最多 5 次)。

### 3. 召回

```
用户消息 → [rewrite: Recall LLM 生成 ≤3 查询]
→ workspace namespace Top8(boost 1.2)
→ global namespace Top4(boost 1.0)
→ 会话摘要 Top3
→ 按 id 去重、按分数排序 → token 预算截断(默认 1600)
→ additionalContext 注入
```

### 4. 降级策略

- Provider 未配置/不可用:daemon 照常启动(`/health` 报告 `degraded`),
  召回返回空上下文,捕获入重试队列。
- 召回超时:HTTP 层超时即返回空,不阻塞宿主。
- 任何 Python traceback 都不注入用户上下文。

### 5. 进程管理

- `bootstrap.ensure_daemon()`:文件锁 + PID 探测 → 派生
  `python -m service.daemon --data-dir ...`(`CREATE_NO_WINDOW` 隐藏窗口)→
  轮询 `/health` → 失败安全重启一次。
- 写操作经 MemoryEngine 写锁串行化(mem0 SQLite 非线程安全)。
